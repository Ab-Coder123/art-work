# Art Work API Integration & Verification Plan

## Operating rule

Work in order. A phase is complete only when its acceptance checks pass and its evidence is recorded below. Do not begin the next phase while the current phase has a failing, skipped-required, or unexplained check. When a check fails, fix the current phase and rerun its full gate. Keep the public site and admin app on their existing ports; do not start or stop servers unless the user asks.

Run focused tests while implementing a phase, then its complete gate before moving on. Use the repository's current `pnpm` scripts and add tests for behavior that is not covered yet. Do not treat a successful build alone as proof of API integration.

## Ten phases

| 9. End-to-end integration and regression | Exercise real public and admin journeys together using isolated test data and a test account; verify mobile/desktop key flows and eliminate runtime/console errors. | Full relevant Playwright suite against isolated app instances; database tests; clean browser console/page errors; test-created content is restored or isolated. |

Release readiness and operational handoff | Finalize CI gates, environment/config documentation, migration status, security/performance review, and operator runbook. | Full `pnpm test`, lint, type-check, and builds; production-like E2E; migration/security checks; no unresolved blocker in the release checklist. |
